# 算力、模拟边界与关键设计

## 配置与资源规划

| 配置 | 用途 | 建议起步资源（需实测确认） | 工作量 |
|---|---|---|---|
| smoke | 工程验证 | 笔记本 CPU，2 线程，8 GB 内存 | 8 客户端，3 轮，2 steps，batch 16，hidden 16 |
| pilot_cpu | 真实数据试跑 | CPU 2–4 线程，8–16 GB 内存 | 约 12 客户端，10 轮，10 steps，batch 32 |
| l20 | 主实验 | 单张 L20，4 CPU 核，16 GB 主存起步 | 60 客户端，每轮 12，100 轮，20 steps，batch 64，hidden 32 |
| l20_dp | 隐私实验 | 与 l20 相同 | 掩码模拟、DP；预算用尽会提前结束 |

这些是资源规划，不是已验证的最低配置或性能承诺。实际显存、CPU 内存和时间由 profile 与实验日志给出。单层小 GRU 可能在 CPU 上同样有效率；GPU 小批次受启动开销影响，不能直接假定 L20 一定更快。

- 家庭共享同一模型结构，一个客户端完成后才处理下一个。GPU 同时驻留一份模型/优化器及一个 batch；不按客户端数复制 GPU 进程。
- CPU 保存每户特征数组和起点索引，批次形成时才构建窗口。避免提前存储 `家庭 × 全时间窗口 × 96 × 特征` 的大张量。
- 以 60 家庭、半年约 8,688 个半小时点估算，6 维 float32 特征约 12 MB（不含原始值、索引、Python、数据框与运行库）。预处理中的 pandas 和 CSV 解压更可能成为内存/磁盘瓶颈。
- 32 hidden / 6 features 的 GRU 约 3.9k 参数，模型权重很小；实际训练工作集由 batch、序列长度和框架决定。profile 输出参数数目、进程峰值常驻内存、GPU 峰值已分配内存。
- 原始全量 CSV 约 10 GB，下载/解压预留至少 15–20 GB 空间；先用少量文件或限定半年做 pilot。运行制品的大小以实际目录统计为准。

## 控制训练预算

默认 100 × 12 × 20 = 24,000 个本地训练 step/单次 FL run（未计失败跳过和验证）。用 profile 的实际 step 秒数估算下限，再加入每轮验证、数据加载、写盘耗时。先跑 3–5 轮，使用实测每轮耗时外推；不要把计划中的 250 GPU 小时当成必须消耗的指标。

Centralized 每轮使用 `local_steps × clients_per_round` 个优化器 step；Local 每户使用 `local_steps`，总工作量可能更高。它们用于预测能力参考，不能只比 round 数声称计算公平。需要资源公平时按实际 step、wall time 另作归一化实验。

同一个 GPU 默认只跑一个实验。用 SLURM 脚本申请单卡，按站点要求通过 `sbatch --partition ... --account ...` 指定队列/账户，设置 `ENERGYFL_PYTHON`。本项目不自动租卡、不提交长任务。运行阶段恢复到最后完整轮；若需要跨硬件改变 device，创建新实验，当前严格 resume 不允许改配置。

## 模拟的含义

`simulation.py` 一次性生成所有轮次/所有客户端的公开资源 trace。改变 scheduler 不改变 trace。设备等级不随用电量分配，也不读取 loss，以免将私有信号加入调度决策。

- 时间 = 参考训练步耗时 / speed + 上下行模型字节 / 带宽 + 往返延迟；加入固定种子的轻微扰动。
- 内存预算用参数与 batch 激活量的粗略公式检查，**不是模拟 Python 框架总内存**。
- 能源预算为无量纲工作单位，**不是焦耳、瓦特或真实电池续航**。
- 掉线和超时在训练前由模拟 trace 决定；真实 GPU 跳过最终无法提交的本地训练，节省研究算力。因此 wall time 不能解释为分布式部署时间。
- 有掉线/超时的轮次等待 deadline；幸存者不足则整轮不更新、不增加 DP release 次数。被选中但掉线的客户端仍有参与机会记录。
- `modeled_round_bytes` 对所选客户端计完整传输，是简化的上界模型；掩码开销是显式假设，**不是捕获的真实网络数据或 SecAgg+ 测量**。
- `calibration_source` 保留校准依据；资源配置变化形成新实验。未经校准也能验证程序，但报告必须标为假设场景。

## 量化与部署分配

`compress` 在 CPU 上对同一 checkpoint 导出 FP32/动态 INT8，固定线程、batch=1、20 次 warm-up，报告 median/P95 延迟、文件大小及验证集 MAE。按误差容忍度、大小预算、模型化延迟为各 profile 分配版本；没有可行版本时显式返回 null。

分配的内存检查仅使用序列化大小，是必要非充分条件；真实部署还需测量运行时内存。FL 全程聚合同一 FP32 结构，不聚合量化参数。不会假定 INT8 必然更快或在所有边缘芯片上可用。

## 后续里程碑

真实 Flower SecAgg+ 的协议适配与协议字节计量尚未完成。本版先让数据、学习、模拟与证据归档能够独立验证；后续替换聚合后端时需保留固定分母、裁剪和预算语义，并单独测试协议阈值、编码误差及不同阶段掉线。不要把此缺口写成已经完成。


## 自动校准

使用 `calibrate` 即可将测量结果写入独立配置，避免手工复制：

```powershell
python -m energyfl calibrate --config configs/pilot_cpu.json --out-config configs/pilot_cpu.calibrated.json --report reports/pilot_setup/profile.json
```

默认重复测量3次，使用每步耗时中位数。配置保存报告路径、SHA256与工作负载指纹；模型、数据、batch、device或线程改变时训练会要求重新校准。调度策略/随机种子可以改变而复用同一校准，使对照实验使用一致参考性能。已保存实验的副本使恢复时不依赖原测量文件仍在原处。

校准只替换参考计算耗时，不会把假设带宽、内存预算、设备速度倍率自动变成实测值。
