# 实验方案：哪些已经确定，哪些由pilot确认

“冻结实验方案”是指在查看测试集结果之前保存最终配置，不是要求暂停开发、等待教师批复或由使用者手动决定每个参数。可以按下面的默认值立即运行自动化pilot。

## 需要pilot数据才能确认的内容

1. **数据资格**：指定时间段是否有足够完整的训练记录、验证集是否有有效窗口。若不够，记录原因后改 cohort/日期，而不能按测试误差挑家庭。
2. **实际性能**：CPU与L20的每步时间、内存和合理总轮数。由校准和短跑测量，不靠手工猜数。
3. **学习与噪声尺度**：默认学习率/轮数能否让验证误差下降；裁剪阈值是否导致噪声完全淹没信号。若必须调整，仅在训练/验证集上做有限候选比较，并保存尝试记录。
4. **时间指标口径**：若报告time-to-target，需在pilot后预先确定统一的验证误差阈值；未达到的实验保留为未达到。当前代码不自动选取一个对某调度器有利的阈值。

这些是基于实测结果的技术判断。它们不妨碍现在下载数据、预处理、自动校准和运行pilot。

## 测试集什么时候使用

pilot和调参阶段只查看训练/验证指标。正式实验矩阵及参数固定后，执行独立 `test`。非DP用最佳验证checkpoint，DP使用最后checkpoint；每个run只测试一次，测试后该run不再继续训练。多种子训练不需要彼此等待，但要使用同一套冻结配置规则。

冻结意味着保存数据manifest、配置、源码快照和选择依据，不表示禁止发现代码错误后修正；修正时新建实验版本，清楚标记哪些结果需要重跑。
